# Yandex Music · Stream Deck + (Windows)

Плагин плеера Яндекс Музыки для Stream Deck: живое превью окна, обложка и исполнитель
текущего трека, транспортные кнопки и управление громкостью аудиосессии.
Не использует Voicemeeter, не записывает звук, не требует администратора и не открывает сетевой сервер.

> С 2026-11-07 код живёт в отдельном репозитории. Микшер Windows вынесен в
> [`streamdeck-app-mixer`](https://github.com/). Исходный монолитный репозиторий
> `D:\git\streamdeck` остался исследовательским (MiniFuse Desk).

## Состав

- `src/` — Node.js-логика: `plugin.mjs` (вход), `player-control.mjs` (кнопки и info-панели),
  `window-capture.mjs` (превью окна и роли валкодеров), `audio.mjs` (аудиосессия
  Яндекс Музыки через мост), `bridge.mjs` (клиент JSON-протокола), `render.mjs` (helpers SVG).
- `native/AudioBridge/` — автономный .NET-мост к Windows Audio Sessions API
  (громкость/mute сессии `Y.Music.exe` / `YandexMusic.exe`).
- `native/WindowCapture/` — автономный .NET-захват окна (PrintWindow) + метаданные
  медиасессии и UI Automation для старой UWP Яндекс Музыки.
- `plugin/` — манифест, иконки (генерируются), layout валкодера, UI инспекторов, лицензии.
- `scripts/` — сборка, генерация профиля, проверки.
- `tests/` — юнит-тесты (`node --test`).

## Сборка и установка

1. Бэкап: `pwsh -File scripts/backup.ps1`. Копируются данные `%APPDATA%\Elgato\StreamDeck`
   и ветка HKCU StreamDeck; файлы профилей проверяются SHA-256. Бэкап может содержать
   приватные настройки — не публиковать.
2. `npm ci`, `npm test`, `npm run build` (.NET SDK 10, Node.js 20+).
3. `npx streamdeck validate dist/local.tux.yamusic.sdPlugin`.
4. `npx streamdeck pack dist/local.tux.yamusic.sdPlugin -o dist`, открыть
   `dist/local.tux.yamusic.streamDeckPlugin` и подтвердить установку плагина.
5. Открыть `dist/YandexMusic.streamDeckProfile` и импортировать **новый** профиль
   **Yandex Music**: шесть кнопок управления и четыре секции превью.
   У пакета собственные UUID; существующие профили не меняются.

## Действия

| Действие | Назначение |
|---|---|
| Окно приложения (валкодер) | Живые снимки окна (~2 к/с), бегущая строка «исполнитель — трек», таймер. Для целого табло — на все четыре валкодера |
| Музыка: обложка трека | Обложка на всю кнопку (кэш в памяти) |
| Музыка: исполнитель | Имя исполнителя крупным текстом |
| Музыка: предыдущий / пауза-пуск / следующий | Транспорт через UI Automation одного окна Яндекс Музыки |
| Музыка: повтор / перемешивание / лайк | Переключатели; золотая рамка — включённый режим |

Роли валкодеров (по умолчанию, меняются в настройках «Окно приложения»):
**первый** — перемотка ±5 с за шаг, нажатие — пауза/пуск; **четвёртый** — громкость
аудиосессии Яндекс Музыки ±2%, нажатие — mute. Остальные не меняют ничего.

## Особенности Windows

- Команды вызывают только известные элементы интерфейса **одного** окна Яндекс Музыки
  через UI Automation: нет глобальных медиаклавиш и смены фокуса. Если окно/кнопки
  недоступны или найдено несколько окон плеера — команда отклоняется с предупреждением.
- Громкость/mute меняются только для единственного найденного EXE `Y.Music.exe` /
  `YandexMusic.exe` с аудиосессией; нет переключения на master volume или браузер.
- Снимки обрабатываются в памяти, не записываются на диск и не передаются по сети.
  Окно не должно быть свёрнуто; PrintWindow поддерживается не всеми приложениями
  (возможен чёрный кадр). Вручную выбранное окно проверяется по HWND/PID; после
  перезапуска приложения выберите его снова.

## Проверки

```powershell
npm test
pwsh -File scripts/check-music-profile.ps1
./dist/local.tux.yamusic.sdPlugin/bin/native/AudioBridge.exe --self-test
```

Self-test создаёт **собственную беззвучную** аудиосессию и проверяет volume/mute/unmute
только в ней; пользовательские приложения и master volume не меняются.

Приёмка на устройстве (запущенная Яндекс Музыка): добавить четыре одинаковых действия
«Окно приложения» — ожидается цельная нижняя полоса окна, бегущая строка и время трека;
пауза/смена трека останавливают/обновляют таймер; переключение верхними кнопками меняет
только Яндекс Музыку; вращение первого валкодера даёт ±5 с без выхода за границы трека,
четвёртого — ±2% громкости сессии.

## Технический долг

1. **Обязательная миграция на `@elgato/streamdeck` v2+.** Сейчас WebSocket-протокол
   Stream Deck реализован вручную через пакет `ws` (`src/plugin.mjs`). Это жёсткое
   требование Elgato для DRM и публикации в Marketplace: Node.js-плагины должны
   использовать официальный SDK. Вместе с ним поднять `SDKVersion` до **3** и
   `Software.MinimumVersion` до **6.9+** (сейчас 2 / 6.6).
2. **UUID с префиксом `local.`** (`local.tux.yamusic`). Перед публикацией в магазин
   переехать на вендорное пространство (например, `com.tux.yamusic`). Смена UUID —
   новая идентичность плагина. Решить до первой отправки в Maker Console.
3. **Дублирование кода** с репозиторием `streamdeck-app-mixer` (`bridge.mjs`, helpers
   рендеринга, протокол моста). Рассмотреть общую библиотеку, когда оба плагина
   стабилизируются.
4. **DRM-требования к файлам**: распространяемые файлы должны быть неизменяемы в рантайме,
   манифест не должен читаться в рантайме. Проверить перед сабмитом.
5. **UI Automation против Яндекс Музыки** — хрупко при обновлениях приложения: элементы
   интерфейса могут переименоваться, и команды начнут отклоняться. Нет автоматического
   повторного поиска; требуется ручная приёмка после каждого обновления плеера.
6. **PrintWindow** может давать чёрные кадры для некоторых окон; таймер старой UWP
   читается из известных элементов интерфейса и ломается при редизайне.
7. **Громкость/mute привязаны к полному пути EXE**. Обновление приложения со сменой
   пути потребует новой аудиосессии под новым путём; старый путь не находит сессию.
8. **Иконка-заглушка** («♪», генерируется `scripts/build-icons.ps1`). Для магазина
   нужен artwork и галерея скриншотов.
9. **Нет CI.** Тесты запускаются вручную; добавить GitHub Actions (минимум `npm test`).
10. **Локализация**: UI и тексты действий только на русском — для магазина нужна
    английская версия.
